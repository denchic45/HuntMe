# HuntMe Backend

Backend платформы HuntMe для подбора ИТ-специалистов: профили кандидатов и компаний,
подтверждение квалификации тестированием, поиск и подбор кандидатов, приглашения
от работодателей и доступ к контактам после согласия кандидата.

## Стек

- Go 1.26.8, стандартные `net/http` и `encoding/json`.
- PostgreSQL 16, драйвер и пул соединений `pgx/v5`.
- Keycloak: авторизация по JWT, роли `candidate` и `employer`.
- Goose: миграции базы данных.
- Docker Compose: локальная инфраструктура.
- Poppler (`pdftotext`): извлечение текста из PDF-резюме.

Используется один `http.ServeMux`. Каждый пакет обработчиков регистрирует полные
пути через `RegisterRoutes`. Проверка JWT выполняется в middleware, доступ к БД —
через передаваемый обработчикам `pgxpool.Pool`.

## Подготовка проекта

Для запуска в контейнерах нужны Docker с Compose v2 и Bash. На Windows можно
использовать Docker Desktop и WSL либо Git Bash с доступной командой `docker`.
Go на хосте нужен только для локальной разработки и запуска тестов.

Настройте `.env` **в корне репозитория**, рядом с `docker-compose.yml`:

| Переменная | Назначение |
|---|---|
| `POSTGRES_USER` | Пользователь БД приложения |
| `POSTGRES_PASSWORD` | Пароль пользователя БД |
| `POSTGRES_DB` | Имя БД приложения |
| `CONNECTION_STRING_DB` | Подключение backend и Goose к БД |
| `KEYCLOAK_DB_PASSWORD` | Пароль отдельной БД Keycloak |
| `KEYCLOAK_ADMIN_USER` | Администратор Keycloak |
| `KEYCLOAK_ADMIN_PASSWORD` | Пароль администратора Keycloak |
| `CORS_ALLOWED_ORIGIN` | Точный origin frontend, например `http://localhost:5173` |

Формат строки подключения **в Docker**:

```text
postgres://<user>:<url-encoded-password>@database:5432/<database>?sslmode=disable
```

Замените значения в угловых скобках. Для уже созданных БД сохраняйте действующие
учётные данные: редактирование `.env` само по себе не меняет пароль внутри БД.
Не публикуйте `.env` и не передавайте административные пароли во frontend.

## Запуск проекта

Основной файл запуска — [`start-services.sh`](../start-services.sh).
Команды выполняются **из корня репозитория**, не из `backend`:

```sh
bash ./start-services.sh
```

Скрипт запускает PostgreSQL приложения, PostgreSQL для Keycloak, Keycloak,
миграции и Go backend. Миграции находятся в `migrations/sql`; backend запускается
после их успешного применения. Frontend и gateway этим скриптом не запускаются.

### Пересборка после изменения кода или миграций

Скрипт использует `docker compose up -d` без `--build`. Чтобы существующие образы
получили изменения, сначала пересоберите их:

```sh
docker compose stop backend
docker compose build migrations backend
bash ./start-services.sh
```

В текущей версии схемы миграция `00007_testing_and_invitations.sql` добавляет
попытки тестирования, снимки вопросов, приглашения и метаданные банка заданий.
Существующие миграции не нужно применять вручную повторно.

### Почта и адреса сервисов

Для локальной проверки писем поднимите его отдельно:

```sh
docker compose up -d mailpit
```

| Сервис | Адрес |
|---|---|
| Backend API | [http://localhost:8081/api/v1](http://localhost:8081/api/v1) |
| Keycloak | [http://localhost:8080](http://localhost:8080) |
| Почта Mailpit | [http://localhost:8025](http://localhost:8025) |
| PostgreSQL приложения с хоста | `localhost:5433` |

## Локальная разработка

Чтобы запускать Go-процесс на хосте, сначала поднимите сервисы через скрипт,
затем освободите порт остановкой контейнера backend:

```sh

docker compose stop backend
cd backend
go mod download
```

Перед `go run` задайте окружение процесса. Пример для Bash:

```sh
export CONNECTION_STRING_DB='postgres://<user>:<url-encoded-password>@localhost:5433/<database>?sslmode=disable'
export CORS_ALLOWED_ORIGIN='http://localhost:5173'
go run .
```

Замените параметры БД действующими значениями. Локальный Go-процесс не читает
корневой `.env` автоматически. В PowerShell переменные задаются через `$env:ИМЯ`.
Адрес сервера по умолчанию — `:8081`; для прямого запуска его можно изменить через
`HTTP_ADDR`. Для обработки PDF установите Poppler и добавьте `pdftotext` в `PATH`.
Автоматическая перезагрузка Go-процесса не настроена: после изменения кода перезапустите его.

## Авторизация и основные возможности

Защищённые запросы передают `Authorization: Bearer <access_token>`.
Backend проверяет RS256-подпись, issuer, audience `huntme-api`, сроки токена,
`typ=Bearer`, подтверждение почты и realm role нужного кабинета.
Профиль пользователя определяется по `sub` из токена.

- **Кандидат:** собственный профиль, приватность и извлечение текста PDF-резюме.
- **Работодатель:** профиль компании, поиск и объяснимый подбор по подтверждённому
  направлению кандидата.
- **Приглашения:** предложение с компанией, описанием, способом связи и диапазоном
  зарплаты в рублях; статусы `sent`, `accepted`, `rejected`.
- **Контакты:** доступны работодателю после принятия именно его приглашения.
  Поиск и подбор возвращают карточки без контактов.


Спецификация находится в [`api/openapi.yaml`](../api/openapi.yaml).
Она пока может расходиться с добавленными маршрутами тестирования и приглашений;
актуальная регистрация маршрутов находится в `mux.go` соответствующих пакетов.

## Ограничения MVP

- Отсутствие банка заданий, и эндпоинты тестирования не готовы, в связи со сложной проработки командой.
- Интеграция ФСП пока возвращает 501. Вакансии, самостоятельные отклики и регулярные
  задания работодателей не реализованы.
- PDF endpoint извлекает текст; структурированное распознавание резюме и генерация
  стандартизированного PDF-профиля не реализованы.
- Скрытие профиля прекращает поиск и новые приглашения, но не отзывает доступ,
  предоставленный ранее принятым приглашением.
- Экраны frontend с локальными mock-данными требуют подключения к этим endpoint.
- Перед публичным запуском необходимо убрать получение admin token Keycloak из
  браузера в `frontend/src/api/endpoints/auth.ts`, исключить административные пароли
  из клиентской сборки и настроить подтверждение почты. Backend-проверка JWT
  не устраняет этот риск регистрации.

Конфигурация Compose предназначена для локальной разработки; Keycloak запускается
в режиме `start-dev`. Данные рабочих БД хранятся в Docker volumes.
Обычный `docker compose down` сохраняет их; `down -v` удаляет volumes и данные.
